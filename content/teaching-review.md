# 入门教学复核 · 2026-10-29

本轮使用 teach 技能重审七个入门步骤。目标是先读懂一个最小程序为什么要补依赖，再进入 LoongSuite 源码。审查不等于真实用户已经理解；没有新增“已掌握”学习记录。

## 原先的问题与修复

- 第 6 步同时讲 GORM、规则模块、三轮准备，读者还不知道新增代码为什么会编译失败。现在只用 demo 和外部 observer，实际展示新增调用、缺依赖错误、修复原 go.mod、构建与运行输出。
- 原图只高亮节点，无法说明缺口。现在新增调用被标出，缺依赖时路径受阻并显示真实错误；构建阶段显示记录库实现接入，运行阶段显示调用 Record。
- 业务与探针仓库的 go.mod 混在一起。现在入门与源码页都明确：业务可以只有原来一份 go.mod，LoongSuite 的模块文件属于另一个仓库。
- 入门过早出现 AST/DST、GOPATH、复杂 context 和传播格式。现在依次学习调用、找代码、构建、额外动作和记录关系，具体机制留在后续章节。
- 错误答案只有笼统提示。现在七页每个选项都有针对误解的反馈，第 6 页还可实际操作“补配置 → 检查构建 → 运行”的教学练习。
- 故事之后重复一遍词典、流程和代码。现在折叠为可选复习，默认保留目标、故事、练习、自我解释题与结论；第 6 步与真实 LoongSuite 的联系继续展开。

## 七步复核表

| 步骤 | 只解决的主要问题 | 可观察的变化 | 理解检查 |
| --- | --- | --- | --- |
| 1 普通函数 | 有业务结果，为什么仍不知道过程？ | 同一查询增加开始/结束记录 | 返回值能否直接告诉耗时？ |
| 2 包与模块 | import 路径怎样对应本地目录？ | module 前缀与 room 子目录对应 | 改 module 后旧 import 能否照用？ |
| 3 go.mod | 我的项目与外部依赖怎么区分？ | 同一文件里的 module 与 require | 谁是当前模块，谁是外部模块？ |
| 4 构建与运行 | 生成程序和执行代码发生在何时？ | go build 产物，再启动程序 | 改规则后旧程序会自动变化吗？ |
| 5 前后动作 | 工具找哪里，额外做什么？ | 规则定位 FindRoom，进入/退出函数被调用 | 只有文字规则，没有可执行函数能记录吗？ |
| 6 补依赖 | 加了一行调用，为什么编译失败？ | 新调用 → 缺依赖错误 → 原 go.mod 补 require/replace → 构建 → 运行输出 | 四种配置组合即时反馈；构建成功是否已经打印记录？ |
| 7 请求记录 | 相同请求与父子关系如何区分？ | 三张记录共用 A，父操作依次为 01、02 | 数据库的 Parent 应指向 02 还是请求编号 A？ |

## 验证与边界

- `node scripts/check-teaching-deps.mjs` 在隔离临时目录里真实调用 Go 构建、运行产物，并对照页面五个步骤。环境禁用网络模块下载，不修改 业务项目。
- `node scripts/check.mjs` 检查七个入门页、40 个实例、42 种情况、176 个段落、离线单文件语法、滚动选择、练习配置与状态重置。
- 第 6 页浏览器练习是教学推演，不在浏览器执行 Go；它解释普通 Go 的依赖关系，不是 LoongSuite 自动插桩验收。
- 独立教学审查已闭合原先的内容错配和源码边界问题。实际读者能否用自己的话解释，仍需要读者回答与操作来判断。
- 浏览器实测：四种依赖配置分别反馈缺声明、缺位置或可构建；运行按钮输出两行，变更配置会收起旧结果。1280×720 下滚动进退及 Home 后帧号与场景一致；390×844 下压缩了重复代码展示，无横向溢出。离线页的第 1、3、5、7 步均从首帧开始，复习内容默认折叠，控制台无错误或警告。

## 后续教学的门槛

只有能解释“新调用需要新的实现，原 go.mod 要让构建找到它”，才继续阅读真实规则模块和 Preprocess。没有理解时，继续缩小同一例子，不能用更多源码名词补救。
